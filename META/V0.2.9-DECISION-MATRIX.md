# v0.2.9 Decision Matrix

This matrix defines documentation and review options for a future next-version decision.
It does not authorize publication.

---

## Option A — documentation-only patch

### When to use
Use when:
- VirusTotal is clean or only generic/noisy
- ClawHub refresh succeeds or is pending

### Includes
- `SECURITY.md`
- scanner explanation
- release note
- no code removal

### Benefits
- improves reviewer clarity quickly
- preserves bridge work and architecture continuity
- reduces ambiguity without implementation churn

### Risks
- may not fully satisfy scanner friction if heuristic concern persists
- may still require follow-up gating or packaging decisions later

### Required approval
- explicit user approval before any actual publish movement

### Prohibited actions
- no bridge deletion
- no compiler bridge removal
- no release artifact mutation beyond explicitly approved documentation work
- no assumption that local hash equals ClawHub hash

---

## Option B — stronger runtime gate patch

### When to use
Use when:
- bridge reachability needs tighter controls

### Includes
- explicit bridge-disabled return path
- explicit external-cli mode requirement
- explicit configured compiler path requirement
- timeout requirement
- preserve `shell:false`

### Benefits
- may reduce ambiguity around reachability and execution posture
- strengthens the explanatory story around bounded behavior
- preserves bridge work rather than deleting it

### Risks
- requires future code-change authorization
- could still be insufficient if scanner friction is driven by process-spawn presence alone

### Required approval
- explicit user approval for implementation/code-change lane

### Prohibited actions
- no bridge deletion
- no silent execution enablement
- no publish before triage and review gates are satisfied
- no `shell:true` relaxation

---

## Option C — public-safe split

### When to use
Use when:
- scanner friction persists because of `child_process` / `spawn`

### Includes
- public package excludes external compiler process code
- bridge moved to dev/private/advanced package
- no deletion of bridge work

### Benefits
- may reduce scanner friction for the public package
- preserves bridge architecture in a more bounded distribution model
- creates a cleaner public-facing package boundary

### Risks
- adds packaging and maintenance complexity
- requires future design and implementation authorization
- may complicate documentation and support expectations

### Required approval
- explicit user approval for package-structure change and implementation lane

### Prohibited actions
- no deletion of bridge work
- no retroactive identity collapse claims
- no publish before new split is reviewed and authorized

---

## Option D — pause publish

### When to use
Use when:
- ClawHub / VirusTotal state remains unresolved
- evidence is incomplete
- user has not approved publish

### Benefits
- preserves trust posture
- avoids premature release movement
- gives time for reanalysis, refresh, and documentation review

### Risks
- delays next-version publication
- may extend uncertainty if evidence collection stalls

### Required approval
- no additional approval required to remain paused
- explicit user approval required to leave pause and enter publish review

### Prohibited actions
- no publish while unresolved
- no release mutation to force movement
- no bridge deletion as a panic response
